# 更新候选清单

Updated: 2026-09-01

## U-001 — 免费、许可清晰的现成素材优先

- Status: `NEEDS_DESIGN`
- Category: 美术管线 / 成本控制
- Suggestion: 在玩法稳定前，尽量采用网上已有的免费模型、动画、材质、特效和环境套件，减少自建模工作；后期再针对视觉统一和原创身份替换或改造关键资产。
- Player value: 更快把时间投入到玩法、武器和在线体验验证。
- Policy: 优先 CC0/公有领域；其次为明确允许商业使用、修改和随游戏分发且署名要求可履行的免费许可。来源不明、仅限非商业、禁止修改或再分发条件不适配的素材不得进入公开构建。
- Required support: 素材登记表、来源页面存档、许可证审查、统一比例/材质/骨骼规范，以及关键视觉资产的替换计划。
- Risk: 来自不同作者的素材容易产生画风、比例、骨骼和性能不统一；“免费”不等于可用于商业 Steam 游戏。
- Boundary: 当前只记录策略，不开始搜索、下载、安装或导入素材。
- Ready when: 世界观和基本角色比例确定，并建立首批素材需求清单与许可证登记模板。

## U-002 — 全员同步的阶段抽奖事件

- Status: `NEEDS_DESIGN`
- Category: 对局节奏 / 随机事件 / 在线同步
- Suggestion: 对局进行到特定阶段后，所有玩家同时看到一次短暂抽奖事件，可采用转盘、机器或其他符合世界观的装置。结算后，每名玩家根据抽取结果获得不同等级的奖励。
- Candidate rewards:
  - 临时移动速度、跳跃或回场能力变化；
  - 玩家体型变大或变小，并相应调整受击、碰撞或击退属性；
  - 限时强力武器或不同类别武器；
  - 吸血、防护、弹药、射速、重量或其他临时 Buff；
  - 少量高风险负面/混合结果仅作为待讨论选项，不默认加入。
- Player value: 在中段重置战局、制造共同期待和可分享的混乱时刻，并让落后玩家获得翻盘机会。
- Design concerns:
  - 完全暂停战斗会切断节奏；需要比较“全局短暂停顿”“场外抽取但战斗继续”和“预告后瞬时结算”。
  - 奖励若纯随机且强度差过大，会让领先者无故获胜或落后者继续受罚；应考虑按排名、库存生命或冲击值进行软性追赶修正。
  - 在线版本必须由权威端生成结果并同步，不能由各客户端自行抽取。
  - 转盘/老虎机是表现形式，不应涉及付费、真钱、可交易物或付费抽取；赌场式外观可能影响产品气质，最终应由世界观决定表现。
  - 体型、速度、武器和 Buff 同时存在会快速扩大平衡组合，需要统一持续时间、叠加和互斥规则。
  - 当前生命值只控制受击飞倍率且归零不死亡，因此传统“吸血”概念并不成立；若保留，它实际是通过命中恢复稳定度、降低后续击飞，需要重新命名并清楚表现。
  - 体型变化必须同步处理碰撞体、抓边范围、武器发射点和受击判定，不能只缩放美术模型。
- Minimum prototype: 一局固定触发一次；四名角色从同一奖励表独立获得结果；先只验证三个奖励——移速、体型、临时武器；结果有清晰预告、持续时间和结束反馈。
- Success test: 玩家能在两秒内理解自己和对手获得的效果；事件没有让战斗停滞过久；弱势玩家有翻盘机会但不会直接决定胜负。
- Dependencies: 基础武器框架、Buff 系统、统一随机种子/权威同步设计、对局阶段系统、状态图标与音效提示。
- Boundary: 当前仅记录，不进入 Prototype 0.1.1，也不承诺作为 Prototype 0.2 内容。
- Ready when: 抽奖触发方式、是否暂停、奖励公平算法和首批三种奖励规则确定。

## U-003 — 单向平台与按下键下落

- Status: `TESTED_IN_0_1_2`
- Category: 核心移动 / 地图路线 / 机器人
- Suggestion: 最底层主地板保持永久实体；所有上层平台改为单向平台。角色可以从平台下方起跳穿到上方，下降到平台表面时正常落地和行走；站在上层平台时按一次下方向键可穿过当前平台向下落。
- Player value: 垂直移动更顺畅，避免上层平台变成阻挡跳跃的天花板；玩家能快速切换高度、追击、逃脱或主动放弃高地。
- Collision contract:
  - `Main Floor`：始终参与角色碰撞，按下键不会穿透。
  - `One-Way Platform`：角色上升或脚部仍低于平台顶面时忽略碰撞；角色下降且脚部从平台顶面上方接触时恢复碰撞。
  - 站在单向平台上时，它与普通地面一致，可走、跳、射击和承受击退。
  - 主动下落只暂时忽略“当前脚下的那一块平台”，不能同时关闭所有单向平台；穿过当前平台后应能落在下一层平台上。
- Input contract:
  - 使用 `S` 或方向键下的按下瞬间触发，不要求同时按跳跃键，符合用户希望的一键下落。
  - 必须是一次新的按键，不因持续按住而连续穿过多层。
  - 只有角色确实站在单向平台上时才触发；位于主地板、空中或被击飞时按下键不改变碰撞。
- Drop behavior:
  - 触发后给角色一个很小的向下速度，避免仍停留在平台接触面。
  - 忽略当前平台与该角色的碰撞，直到角色头顶或碰撞体上沿已经低于平台底面；另设短超时作为防卡保护。
  - 不使用全局 Layer 碰撞开关，避免一个玩家下落时影响其他玩家。
- Knockback and recovery:
  - 从下方被向上击飞时可以穿过单向平台；随后下降时可落在平台上。
  - 站在平台上受到向下击退时默认不会自动穿透；只有玩家主动按下键才下落，避免一次命中无预警地改变平台规则。
  - 未来的抓边系统只应作用于可抓的平台边缘，并且主动下落后的短时间内不立刻抓回同一平台。
- Bot behavior:
  - 机器人知道主地板不能穿透。
  - 当目标明显位于下层且下落路线安全时，机器人可以主动执行一次下落指令。
  - 机器人不得通过永久关闭碰撞或瞬移来作弊，使用与玩家相同的单平台忽略规则。
- Visual communication:
  - 主地板保持厚重基础结构；单向平台使用更薄的台面、明亮上边缘和可辨认底面，使玩家不用文字也能判断哪些平台可穿越。
  - 主动下落可加入短暂下蹲/下压动作和轻量尘效，但不作为首版必需条件。
- Networking requirement: 正式在线版由权威端确认“当前支撑平台”和下落状态；同步的是下落动作/碰撞状态，而不是让每个客户端独立猜测。
- Open design choice: 子弹和爆炸物是否被单向平台阻挡应按武器分别定义，不与角色单向碰撞规则强行绑定。Prototype 0.1.2 可暂时保持现有子弹行为，避免同时改动射击平衡。
- Minimum test matrix:
  - 从每块上层平台正下方单跳/二段跳穿过并落到台面；
  - 在每块上层平台按一次下键，只穿过当前一层；
  - 在主地板按下键不下落；
  - 连续按住下键不会穿透多层；
  - 两名角色分别站在同一平台时，一人下落不影响另一人；
  - 上升击飞可穿台、下降击飞可落台；
  - 机器人能在目标位于下层时偶尔正确下落且不会坠出场外。
- Success test: 玩家第一次看到地图即可理解上层平台能上下穿越；下落动作响应清楚且没有连续漏层、卡边或误穿主地板；机器人遵守相同规则。
- Dependencies: 平台类型标记、按角色/平台对管理的临时碰撞忽略、支撑平台检测、机器人垂直路线判断。
- Boundary: 当前只完成设计和版本提案，尚未修改 Unity 代码。
- Proposed package: `updates/VERSION_0_1_2.md`。

## U-004 — 玩家之间无实体碰撞

- Status: `TESTED_IN_0_1_2`
- Category: 核心移动 / 在线稳定性 / 多人可读性
- Suggestion: 玩家角色之间不产生刚体推挤、阻挡或踩踏，可以直接互相穿过；玩家仍然能够被对方的子弹、爆炸、近战触发区和其他攻击命中。
- Player value: 四人混战时不会因身体卡位、出生点重叠或网络误差产生不可控推挤，平台边缘的移动更加直接。
- Collision contract:
  - `Player Body` 对其他 `Player Body` 不发生实体碰撞。
  - 玩家对主地板、单向平台、场地机关和危险区域的碰撞保持不变。
  - `Projectile/Hitbox` 对玩家的命中检测保持有效，不能因为关闭身体碰撞而误关攻击判定。
  - 玩家重叠时不互相施加速度、质量或击退；击退只能来自武器、爆炸、机关或明确设计的技能。
- Visual concern: 两名玩家完全重叠时会难以辨认。角色需要清晰配色/轮廓，并可给每名玩家的视觉模型设置极小的只读景深偏移；物理位置仍保持同一2D平面。
- Future boundary: 如果以后加入抓取、冲撞或近战推人，这些能力使用独立触发区和技能规则，不重新启用全局身体碰撞。
- Networking value: 减少玩家刚体相互作用带来的预测分歧和位置抖动，但不能替代正规的移动同步与命中权威。
- Minimum test matrix:
  - 玩家和机器人可以双向穿过且不减速、不弹开；
  - 重叠时双方仍能被子弹分别命中；
  - 重生在相同位置不会卡住或产生爆炸式速度；
  - 玩家穿过彼此时仍分别与地板和单向平台正确碰撞；
  - 重叠状态下角色身份仍可辨认。
- Boundary: 当前只写入 Prototype 0.1.2 提案，尚未修改碰撞层或代码。
- Proposed package: `updates/VERSION_0_1_2.md`。

## U-005 — 隐藏生命/击飞数字并降低单发累积

- Status: `TESTED_IN_0_1_2`
- Category: HUD / 战斗可读性 / 对局时长
- Suggestion: HUD 不再显示 `HP` 和 `Knockback x` 数字。后台继续保存受击累积值，并维持“被命中越多，后续受到的击飞越强”的规则；库存生命数仍然显示。略微降低基础子弹造成的后台累积，使一条命持续更久。
- Player value: 减少测试感很强的数值界面，让玩家通过角色反馈理解危险程度，同时降低少量连续命中快速进入最高击飞区间的情况。
- Hidden-state contract:
  - 后台仍保存 0–100 的内部稳定度/受击累积数据，不改变“归零不直接死亡、出界才掉命”的规则。
  - HUD 隐藏具体 HP、内部累积值和击飞倍率，不向玩家显示伪装成传统血条的数值。
  - 库存生命数必须保留，因为它直接决定比赛胜负。
- Non-numeric feedback:
  - 每次命中保留明确闪光、短停顿或受击动画；
  - 随着内部累积提高，逐步增强身体不稳定动画、受击音高/音色和被大幅击飞时的拖尾；
  - 只使用少量清晰阶段，不用另一套隐蔽数字或复杂图标替代被移除的 HP；
  - 新手提示只需说明一次“被打得越多，就越容易被击飞”。
- Provisional tuning: 当前基础子弹每次降低 11 点内部稳定度；Prototype 0.1.2 的首轮候选值为 9 点，约从 10 次命中进入零稳定度延长到 12 次。保持基础击退和 1.0x–3.5x 曲线不变，以便只测试累积速度。
- Design warning: 若完全没有阶段反馈，玩家会把后期强击飞误认为随机或网络问题；因此“隐藏数字”不等于“隐藏状态变化”。
- Minimum test matrix:
  - HUD 只显示玩家身份和剩余生命，不显示 HP 或倍率；
  - 后台累积仍正确影响击飞，重生后正确重置；
  - 从满状态到最高击飞区间所需命中次数符合候选值；
  - 玩家不看数字也能从反馈大致判断自己处于稳定、受压或危险阶段；
  - 对局时长有所增加，但不会出现长时间无法完成一次击杀。
- Boundary: 当前数值 9 只是首轮测试候选，不是最终平衡结论；尚未修改 HUD 或伤害代码。
- Proposed package: `updates/VERSION_0_1_2.md`。

## U-006 — AI难度档位，默认Easy

- Status: `TESTED_IN_0_1_2`
- Category: 机器人 / 难度 / 原型测试
- Observation: 当前机器人在垂直差小于约 1.5、水平距离小于 13 时会持续按住开火，决策间隔仅约 0.25–0.55 秒，且会持续追向玩家；实测反馈为强度偏高。
- Suggestion: 建立 `Easy / Normal / Hard` 三档机器人行为预设，Prototype 0.1.2 默认使用 `Easy`。难度只影响思考、射击与路线决策，不改变角色移动速度、跳跃高度、武器伤害、生命数、重力或基础物理规则。
- Easy target behavior:
  - 决策/反应间隔约 0.65–1.0 秒，给新玩家明显反应窗口；
  - 使用短射击段和停火间隔，不在满足条件后永久连续开火；
  - 偶尔停顿、过早跳跃或放弃一次并非致命的追击，但不故意走出地图；
  - 目标进入同一高度后再开火，降低隔着平台边缘精准压制的频率；
  - 使用单向平台下落时更保守，优先保证不会无意义坠出场外。
- Normal target behavior:
  - 接近当前原型的决策速度，但增加合理射击段和停火窗口；
  - 能使用上下平台追击，并具备正常的边缘回避。
- Hard target behavior:
  - 更短反应时间、更稳定的射击节奏和更积极的平台路线选择；
  - 可以更早识别玩家的移动趋势，但不得读取未来输入、瞬移、无视冷却或获得额外伤害。
- Fairness rule: 所有档位与玩家共享同一 `FighterMotor`、武器冷却、伤害和碰撞规则；难度来自决策质量，而不是隐藏属性加成。
- Prototype interface:
  - 默认档明确为 `Easy`；
  - 原型阶段可保留开发者快速切换预设的方式，以便同一构建对比三档，不要求为此制作完整菜单；
  - HUD 可以显示 `BOT — EASY`，但不恢复被移除的 HP/击飞数值。
- Evaluation warning: U-005 同时降低受击累积速度，也会让对局更容易持续。测试时应使用快速难度切换分别比较 AI 行为和伤害累积，避免把两种变化混为一谈。
- Minimum test matrix:
  - 新开局默认加载 Easy；
  - Easy 有清楚的停火/反应窗口，玩家能接近、跳过或撤离；
  - 三档机器人使用完全相同的角色与武器数值；
  - Normal 明显比 Easy 更积极，Hard 明显比 Normal 更稳定，但都不作弊；
  - 三档均不会因新单向平台规则频繁自杀；
  - 重生后难度预设保持不变。
- Success test: 初次玩家能在 Easy 下理解移动、射击和击飞规则而不会持续被压制；提高档位后挑战主要表现为决策更快、更稳定，而不是伤害突然增加。
- Boundary: 已在 Prototype 0.1.2 实现行为预设；完整难度菜单和长期自适应 AI 仍不在本版范围。
- Proposed package: `updates/VERSION_0_1_2.md`。

## U-007 — 两人互联网Host/Join联机验证

- Status: `DEFERRED`
- Category: 网络 / 房间 / 玩家所有权 / 互联网连接
- Suggestion: 第一版联网只支持两名玩家。玩家一创建并主持游戏，玩家二从另一台电脑通过互联网加入；成功加入后，远程玩家替换当前AI，与房主完成一场一对一对局。
- Scope decision:
  - 一名 `Host` 同时承担本地玩家和权威游戏服务器；
  - 一名远程 `Client` 只控制自己的角色；
  - 联机房间上限固定为2，不在首轮扩展到4人；
  - 连接成功后不保留AI参战，形成纯玩家对玩家对局；
  - 离线沙盒仍可保留AI，不等于从项目中删除机器人系统。
- Connection experience:
  - 目标体验是“创建房间 → 获得加入方式 → 另一台电脑加入 → 双方准备 → 开始比赛”；
  - 正式互联网测试不应要求普通玩家配置路由器端口转发；
  - 直接IP只适合作为开发或局域网诊断路径，不作为默认用户体验；
  - 加入码/大厅/好友邀请的具体实现取决于后续选定的中继或Steam网络方案。
- Authority contract:
  - Host 权威确认角色位置、速度、平台状态、子弹生成、命中、内部受击累积、击飞、出界、生命和重生；
  - Client 发送输入而不是直接宣布位置、命中或胜负；
  - Client 可预测自己的移动以降低输入延迟，Host 校正最终状态；
  - 远端角色使用插值显示，避免每个网络包都造成视觉抖动；
  - Unity物理不做两端独立确定性模拟，避免击飞结果逐步分叉。
- Ownership/refactor requirement:
  - 当前 `PrototypeBootstrap` 直接创建玩家和AI，未来需要拆分为“比赛规则、玩家生成、输入来源、网络所有权和表现层”；
  - `HumanController` 只读取本机拥有角色的输入，不能同时驱动远程角色；
  - AI只能作为离线输入来源，连接远程玩家后由网络输入来源替代；
  - 单向平台、无玩家身体碰撞和隐藏后台数值都必须先有明确权威同步规则。
- First disconnect rules:
  - Client 退出或断线时，本局结束并返回等待房间，不在首轮自动由AI接管；
  - Host 退出时房间结束，不做Host迁移；
  - 首轮可不支持对局中重连，但必须显示明确的断线原因并安全退出比赛。
- Technical choice gate:
  - 在实施前比较当前可用的Steam大厅/网络传输、中继式服务和Unity兼容网络框架；
  - 比较项包括互联网穿透、Steam集成路线、成本/配额、维护状态、许可证、Host权威支持、预测/插值能力和Unity 6000.5兼容性；
  - 技术选择具有时效性，正式决策时需要重新查询官方文档，当前不预选或安装网络包。
- Security/fairness baseline:
  - Host 验证射速、输入范围、生成请求和命中结果；
  - 不信任Client上传的生命、伤害、击飞或胜负数据；
  - 首轮是朋友间原型验证，不代表已经具备正式反作弊、举报或公开匹配能力。
- Minimum test matrix:
  - 两台不同电脑、不同互联网连接能够在不手动端口转发的目标路径下加入；
  - Host与Client各自只能控制自己的角色，AI不在联网对局中出现；
  - 移动、跳跃、水平射击、单向平台、命中、击飞、出界、生命和重生在双方画面保持一致；
  - 两名玩家无身体碰撞，但仍能互相命中；
  - 100–150ms往返延迟下仍可操作，远程角色没有持续跳变；
  - Client断线和Host退出都能安全结束房间，不残留失控角色；
  - 同一构建可启动一个Host和一个Client完成整场比赛与重赛。
- Success test: 一名玩家创建房间，另一名玩家从外部网络加入并替换AI；双方能够完成一局且一致看到关键战斗结果，不需要配置端口转发。
- Dependencies: 先稳定并测试Prototype 0.1.2基础移动契约；随后选择网络框架/传输/大厅方案，重构玩家生成与输入所有权，并建立两台电脑的延迟/断线测试条件。
- Boundary: 当前主动推迟，先完成本机离线玩法；不调查或下载网络包、不注册服务、不配置Steam、不改网络代码，也不指定发布日期。只有用户未来重新启用联网里程碑时才进入技术选型。
- Future milestone: `updates/FUTURE_NETWORK_DUEL.md`。

## U-008 — 完整单局流程、胜负与重赛

- Status: `READY_FOR_BATCH`
- Category: 比赛规则 / UI / 本地离线闭环
- Problem: 当前角色生命耗尽后会直接恢复初始生命继续游戏，没有真正的胜者、结算或下一局流程；这只能算沙盒，不能验证一场比赛是否有节奏。
- Suggestion: 建立 `倒计时 → 对战中 → 单次出界/重生 → 最终淘汰 → 胜者展示 → 重赛` 的完整状态机。
- Proposed rules:
  - 双方默认3条库存生命，最后一条耗尽后不再自动复活；
  - 开局3秒倒计时期间不能移动或射击；
  - 每次出界短暂停顿并显示剩余生命，然后在安全出生点重生；
  - 重生后有短暂、清楚可见的保护期，防止AI连续压制出生点；
  - 一方生命耗尽时停止战斗，显示胜者和本局时长；
  - 支持一键重赛，并完全重置角色、内部受击累积、子弹和临时状态。
- Design warning: 不应通过每次出界都播放很长动画来延长对局；派对游戏重赛速度比复杂结算页面更重要。
- Minimum test matrix:
  - 倒计时期间双方无法行动；
  - 每次出界只扣一条生命并正确重生；
  - 最后一条生命结束后只宣布一次胜者，不会自动重置；
  - 重生保护能防止立即连杀，但不会持续到玩家主动攻击后仍无敌；
  - 重赛清除所有旧子弹、速度和后台累积；
  - 玩家获胜和AI获胜都能完成闭环。
- Success test: 不依靠开发者按R，玩家能从开局完成一场有明确胜负的比赛，并在数秒内开始下一局。
- Boundary: 不并入已成形的0.1.2；作为0.1.2之后最优先的未来核心循环候选，不立即实施。

## U-009 — 抓边与一次可学习的回场机会

- Status: `NEEDS_DESIGN`
- Category: 回场 / 技巧 / 击飞反制
- Problem: 当前被击飞离开平台后主要依赖空中转向和二段跳，缺少此前愿景中的“最后一次自救”，边缘攻防还不够丰富。
- Suggestion: 角色在下降、靠近可抓边缘并朝平台方向移动时可以抓住边缘；悬挂后可选择爬上、跳离或按下落放弃。
- Recommended first contract:
  - 每次离地到重新落地之间，最多成功抓边一次，防止无限反复拖延；
  - 只在下降阶段抓边，上升穿过单向平台时不误抓；
  - 主动按下键穿平台后的短时间不抓回同一平台；
  - 抓边时暂停坠落，不能开枪；跳跃键执行翻上/跳离，下键松手；
  - 抓边位置、检测范围和角色手部表现必须一致，避免隔空抓取；
  - 机器人Easy档较少使用，Normal/Hard更稳定使用，但遵守同样的一次限制。
- Design choices still needed: 自动抓边还是必须按住平台方向；悬挂最长时间；翻上是否有短暂无敌；攻击能否把悬挂者打落。
- Success test: 被中等击飞的玩家有一次清楚、可练习的回场机会，但强力击飞和成功守边仍然可以完成淘汰。
- Boundary: 不并入0.1.2；规则仍需单独试玩后再形成版本范围。

## U-010 — 三种基础武器与场内拾取循环

- Status: `NEEDS_DESIGN`
- Category: 武器 / 随机掉落 / 核心内容
- Problem: 当前只有无限水平单发子弹，能够测试击飞公式，却不足以证明“不同武器制造不同空间选择”这一核心乐趣。
- Suggestion: 第一轮武器系统只做三种差异明显的原型，并通过有预告的场内拾取点获取：
  - 连续压制武器：低单发击退、持续控制走位；
  - 近距离爆发武器：射程短、散射或多弹丸、近身击退强；
  - 抛射爆炸武器：射速慢、范围击飞、能制造平台边缘压力。
- System contract:
  - 武器使用统一的数据配置、弹药、射击冷却、命中和击退接口，不为每把枪复制角色逻辑；
  - 拾取出现前有声音/光效预告，生成窗口可预测，避免纯随机立即决定胜负；
  - 强武器使用有限弹药或持续时间，用完回到基础武器；
  - 首轮只允许携带一把拾取武器，不立即实现复杂背包；
  - AI能识别附近武器但不会总比玩家更早知道生成位置。
- Design warning: 不应一开始制作十几把枪。先确认三种攻击节奏确实产生不同路线和笑点，再扩展武器数量与连锁反应。
- Success test: 玩家不看名称也能从射速、声音、弹道和击飞结果分辨三种武器，并会因为掉落位置改变移动路线。
- Dependencies: 0.1.2击飞/平台规则稳定，完整命中反馈，武器数据结构，拾取点和弹药UI。
- Boundary: 不并入0.1.2；属于后续内容里程碑，不立即实施。

## U-011 — 双角色镜头与出界方向提示

- Status: `READY_FOR_BATCH`
- Category: 镜头 / 可读性 / 回场
- Problem: 当前镜头固定。角色被大幅击飞时可能先离开画面、之后才触发出界；玩家无法判断自己在屏幕外的位置和回场方向。
- Suggestion: 镜头在地图允许范围内轻微平移/缩放，尽量同时保留玩家与AI；当角色必须离开画面时，在屏幕边缘显示对应颜色的方向标记和距离/危险变化，而不是让镜头无限拉远。
- Camera contract:
  - 镜头以竞技场为主，不因一颗子弹或短暂跳跃频繁抖动；
  - 缩放和平移有最大范围、平滑时间和安全边距；
  - 平台和出界边界始终保持可理解，不能为了追随被击飞者让主战场消失；
  - 屏外标记只显示身份、方向和危险程度，不重新显示HP数值；
  - 强击飞可有短促镜头强调，但震屏强度有关闭/降低选项。
- Success test: 玩家被击飞出主画面时仍能判断回场方向，主战场不丢失，镜头变化不会影响水平射击判断或造成明显晕动。
- Boundary: 不并入0.1.2；适合与U-008比赛闭环和U-009回场组成后续可读性版本，不立即实施。

## U-013 — 0.1.2 爽感回调：AI、命中与跳跃

- Status: `TESTED_BUILD_IN_0_1_3`
- Category: AI / 击退 / 命中反馈 / 移动手感
- Player feedback: Easy AI 只会跟随玩家；子弹命中后缺少夸张后退，命中效果像是消失；跳跃高度偏低、缺少爽感。

## U-014 — 未来低重力/月球派对模式

- Status: `NEEDS_DESIGN`
- Category: 规则变体 / 空中战斗 / 模式内容
- Suggestion: 未来增加独立的低重力或月球模式，让玩家获得更长浮空、更大的空中射击与变向窗口，并围绕低重力设计专属地图或规则修正。
- Design warning: 不应只把基础模式的全局重力乘低。模式需要同步检查跳跃初速、受击冲量、空中加速度、弹道、爆炸、出界边界、镜头与比赛时长，否则容易形成长时间无法落地或轻微命中直接飞出场外。

- Future test: 比较基础模式与月球模式的空中停留时间、射击命中率、回场成功率、单条生命时长和晕动风险。
