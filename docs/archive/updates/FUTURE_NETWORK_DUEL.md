# 未来网络里程碑 — 两人互联网Host/Join对战

Status: `DEFERRED — LOCAL OFFLINE GAMEPLAY FIRST`  
Date: 2026-09-01

## 目标

让一名玩家创建并主持互联网房间，另一名玩家从其他电脑和外部网络加入。远程玩家替换AI，双方在现有竞技场完成一场一对一比赛。

## 当前优先级

该里程碑已主动推迟。当前只验证一台电脑上的单人对AI玩法、基础手感和内容循环；不开始Steam、互联网联机、局域网联机或网络框架选型。这里的“本地游玩”不自动恢复同一台电脑双人功能。

## 为什么不并入Prototype 0.1.2

0.1.2仍在确定单向平台、玩家无碰撞、隐藏受击数值、伤害累积和AI压力。联机需要同步这些规则；如果先写网络层再改基础规则，会重复重构玩家生成、输入、物理和状态同步。

## 首轮范围

1. 固定两人：一个Host、一个Client。
2. Host创建房间，Client通过加入码、大厅或好友邀请加入；具体入口等待技术选型。
3. 联机对局中远程玩家替换AI，不做第三名玩家或观战。
4. Host权威处理物理、子弹、命中、内部累积、击飞、出界、生命与重生。
5. Client只发送自己的输入，并使用本地预测；远程对象使用插值。
6. 完成等待、准备、开局、一局比赛、结算和重赛闭环。
7. Client断线则结束本局并返回房间；Host离开则关闭房间。

## 明确不纳入

- 四人房间、公开匹配或服务器列表；
- 专用服务器或Host迁移；
- 对局中重连和AI自动接管断线玩家；
- 排位、账号、云存档、语音、举报或正式反作弊；
- 新地图、新武器、抽奖事件和Buff系统；
- 要求普通玩家手动设置路由器端口转发的最终体验。

## 开始前必须决定

- 网络框架与Unity 6000.5兼容性；
- 传输层及Host权威、预测、插值支持；
- 互联网穿透/中继方案；
- Steam大厅/好友邀请是在首轮采用还是后续接入；
- 当前官方价格、配额、许可证、维护状态和发布限制；
- 两台外部网络测试电脑及延迟/丢包测试方法。

这些信息会变化，进入实施前必须基于官方资料重新调查，不能沿用过时印象。

## 验收条件

- 两台不同网络的Windows电脑无需手动端口转发即可连接。
- 双方只能控制自己的角色，联机局中不出现AI。
- 100–150ms往返延迟下，移动与射击仍然可理解和可操作。
- 平台、子弹、命中、击飞、出界、生命和重生在双方保持一致。
- Client断线和Host退出有明确结果，不会留下失控比赛。
- 双方能完成比赛、看到一致结算并发起重赛。

## 启动条件

本机离线玩法达到可持续游玩的质量；用户未来明确重新启用联网方向；之后才进行官方资料技术调查并形成网络选型建议，最后另行批准实施。
