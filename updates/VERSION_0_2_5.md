# Prototype 0.2.5 — 随机掉落、武器模型与黄昏城市背景

Status: `HANDS-ON VERIFIED (single player + 2-instance online)`
Date: 2026-09-02

## 本批内容

延续 0.2.3 之后的多轮用户反馈，全部为当场试玩驱动的迭代。

### 武器系统

- **火箭 → 狙击枪**。定位是"让击退看得见"：弹速 46（近乎瞬达）、击退 6.4、自身后坐力 1.25、冷却 1.5 秒、仅 3 发。取消溅射。
- 试玩后削弱：伤害 16 → **10**。**主要砍伤害而非击退**——内伤会把击退倍率一路推到 3.5×，16 点伤害两三发就把目标推进"一击必飞"区间，问题的根源在这里而不是单发力度。
- **开局武器改为手枪造型**。四把枪形成清晰的长度梯队：手枪 0.42 → 冲锋枪 0.62 → 散射 0.80 → 狙击 1.39（模型单位），远距离也能分辨。

### 随机掉落（取代固定拾取点）

固定点让每局跑法完全一样：同一把枪永远在同一个角落。改为：

- 3 个掉落槽位，开局全空。
- 每 **5.5–9.5 秒**随机投放：随机武器、随机平台、随机位置（边缘内缩，不会掉出场外）。
- **捡走即消失，不在原地重生**；下一把由 `PickupDirector` 决定在别处出现。
- 联机中位置与武器都会变，因此同步从"固定索引位掩码"改为**逐槽位同步**（位置 + 武器 + 是否存在）。

### 第三方素材接入

三份素材全部 **CC0**，已按 `ASSET_POLICY.md` 登记为 TP-001 / TP-002 / TP-003，许可证副本随资产存放。

- **TP-001 Kenney Blaster Kit** — 四把武器模型，手持与地面掉落共用。
- **TP-002 ambientCG MetalPlates006** — 平台 Color + Normal 贴图，**平铺按平台实际尺寸计算**，否则 19 单位宽的主平台会把一块铁板拉变形。
- **TP-003 Kenney City Kit (Commercial)** — 背景建筑。只取包内 `low-detail-building-*` 与 `building-skyscraper-*`，这些本就是为远景设计的。

**枪械模型只用网格，保留包内调色板贴图**（`colormap.png`）。早期版本把材质整体替换成项目配色，结果整把枪变成一个色块——这些模型是靠 UV 映射到调色板取色的，替换材质等于丢掉颜色。

⚠️ **枪口方向必须逐模型记录。** 实测发现 `blaster-m` 的枪口在 +Z，而其余三把在 -Z。统一旋转会让其中一把反向。现在 `WeaponModels` 中每个条目自带 `MuzzleSign`，旋转由数据推导。

⚠️ **朝向翻转用旋转而非负缩放。** 负缩放对程序化方块有效，但对导入模型是镜像而不是转身，法线也会翻。

### 背景美术（两轮）

第一轮做了赛博朋克夜景 + 数百个自发光窗户，用户反馈**"眼花缭乱、刺眼"**——判断失误：背景在 z=13~28、镜头在 z=-29，那些楼在屏幕上只有几十像素高，密集的自发光点只会变成噪点。

第二轮推倒重做：

- 背景建筑改用 **City Kit 真实模型**，三层深度，**全部去掉窗户灯**。
- 每层一个共享平铺材质，越远越亮越偏向天空色（大气透视），靠色调而非细节拉开纵深。
- 天空改为**低对比黄昏渐变**，单个柔和的太阳。
- 整体压暗：Bloom 阈值 1.15 → **1.4**、强度 0.5 → **0.28**，对比度与饱和度下调，平台霓虹亮度全部下调约 30%。

**共享材质是必需的**：一个天际线若每个对象各建一份材质，会产生数百个材质实例。现在整条天际线只用 3 个材质。

## 验证结果

- Windows Development Build：`Build Successful`。
- `-chaosSmokeTest` 通过：`CHAOS_ARENA_023_ASSERTIONS_PASS` 等全部断言。
- 断言已更新为掉落制：槽位数正确、**开局所有掉落必须处于隐藏状态**（由导演调度而非预置）。

## 仍未验证 / 已知限制

- **客户端无预测**，自身移动有一个来回的延迟，实测可感知（U-030）。
- 随机掉落的节奏（5.5–9.5 秒）与 3 槽位上限未经长时间对局验证。
- 狙击枪削弱后的强度未经充分对战验证。
- 背景与平台美术为第二版，仍可能需要继续调暗或调亮。
- 4 人满员从未测试过，目前最多验证到 2 人。
